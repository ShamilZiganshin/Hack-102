# Hack102 — осмотр насосов с телефона

Стенд для Windows x64 объединяет 3D-сцену, паспорта четырёх демонстрационных насосов в PostgreSQL, непрерывный осмотр на NVIDIA GPU и историю показаний.

## Первый запуск на новом ПК с NVIDIA RTX (Windows x64)

Сайт, база PostgreSQL и распознавание запускаются на одном ПК. Для первого запуска понадобится интернет. Используйте полный клон с Git LFS: в нём лежат исходники, SQL, веса и установочный скрипт.

1. Установите драйвер NVIDIA с поддержкой CUDA 12.8, Git for Windows с Git LFS, Python **3.11 x64** с Python Launcher (`py`) и PostgreSQL **17 или 18 x64** с сервером и командными инструментами. Для PostgreSQL оставьте стандартный каталог `C:\Program Files\PostgreSQL\17` или `18`. Скрипт сам установит CUDA-сборку PyTorch.
2. Откройте **PowerShell** под своей обычной учётной записью. Проверьте установки. Первая команда должна показать вашу видеокарту, вторая — Python 3.11, третья — версию Git LFS.

   ```powershell
   nvidia-smi
   py -3.11 --version
   git lfs version
   ```

3. В папке, где хотите хранить проект, выполните команды по очереди. Дождитесь завершения каждой. Если вы уже клонировали репозиторий, откройте PowerShell в его корне и начните с `git lfs pull`. Если скачали **Code → Download ZIP**, выполните команды клонирования ниже, чтобы получить веса из Git LFS.

   ```powershell
   git lfs install
   git clone https://github.com/ShamilZiganshin/Hack-102.git
   cd Hack-102
   git lfs pull
   git lfs fsck
   .\START.bat
   ```

4. При первом старте `START.bat` создаёт окружения, устанавливает зависимости, создаёт базу на локальном порту `55440`, загружает четыре демопаспорта и запускает сервер. Оставьте окно открытым до **READY**. Имя видеокарты и `tensor([1.])` подтверждают тест CUDA. Строка **READY** появляется после проверки готовности моделей ржавчины, масла и трещин.
5. **На этом ПК** откройте [кабинет администратора](http://127.0.0.1:8769/admin). При первом входе логин и пароль — `admin` / `admin`. Задайте свой пароль и создайте учётные записи для осмотра. Отдельно можно открыть [3D-сцену насоса](http://127.0.0.1:8769/viewer.html).
6. **На телефоне** подключитесь к той же локальной сети. На ПК откройте файл `Насос — 3D и мобильный осмотр\Подключить телефон.html`. Установите на телефон сертификат по инструкции на этой странице и отсканируйте **второй QR** для непрерывной камеры. Войдите в кабинет, откройте камеру, разрешите доступ, сфотографируйте QR насоса или выберите насос из списка и нажмите **«Непрерывный осмотр»**. Для демонстрации можно навести камеру на 3D-сцену на мониторе.

**Если возникла проблема.** При ошибке CUDA проверьте `nvidia-smi` и драйвер. При ошибке загрузки весов повторите `git lfs pull` и `git lfs fsck` в корне клона. Если сервер завершился до READY, смотрите `Насос — 3D и мобильный осмотр\outputs\server-error.log`, для PostgreSQL — `private\postgres.log` в той же папке приложения. Если сайт открывается на ПК, но недоступен с телефона, проверьте Wi-Fi и запустите приложенный `ALLOW_LAN.ps1` из папки приложения от администратора. Для подключения из другой сети см. [инструкцию Radmin](RADMIN.md).

Для следующих запусков используйте тот же `START.bat` в корне клона. Чтобы обновиться, сначала выполните `git pull --ff-only` в этой папке и снова запустите `START.bat`.

## Обновление подготовленного RTX-ноутбука

Скачайте [архив для RTX](releases/Hack102-RTX.zip) через GitHub или получите его командой `git lfs pull`. Распакуйте содержимое в существующую папку Kiber102-Windows-GPU рядом с .venv, подтвердите замену файлов и запустите **START_RTX.bat**. Этот архив предназначен для уже установленного стенда. Скрипт проверяет CUDA и БД, при необходимости запускает её и перезапускает сервер этого проекта. Журналы находятся в outputs внутри каталога приложения.

## Демонстрация

Сфотографируйте QR насоса из сцены или выберите его в списке. Нажмите «Непрерывный осмотр». Кнопка «На весь экран» разворачивает камеру, «Выйти» возвращает страницу. В кадре отображаются значения, краткие ALERT и действия. Подробности и графики доступны ниже. Старая ссылка ar.html открывает главную страницу.

В демонстрации насос 001 работает в норме, 002 показывает перегрев и повышенную гармонику 1×, 003 — низкое давление и повышенную 2×, 004 — повышенные вибрацию, ток и ВЧ-шум. Вибрационные примеры взяты из 500 почасовых записей. Демо воспроизводит их ускоренно. Остальные демопоказания моделируются. Рекомендации служат подсказками для проверки. Автономный просмотр доступен в файле «Насос — свободный 3D.html».

Исходники сайта и моделей находятся в каталогах приложения и трёх детекторов. Базовые таблицы и демонстрационные паспорта создаются из SQL в Насосы_БД. Рабочая БД, ключи и параметры подключения создаются на компьютере запуска.

## Телефон и RTX в разных сетях

Подключите оба Windows-ПК к общей сети Radmin VPN. На ПК рядом с телефоном запустите **START_RADMIN.bat** и укажите Radmin-IP RTX и локальный Wi-Fi-адрес ПК. Камера телефона открывает RTX-сайт через HTTPS этого ПК. Порядок установки сертификата, второй QR и диагностика сети описаны в [инструкции для разных сетей](RADMIN.md). Для установки без клона скачайте [архив шлюза](releases/Hack102-Radmin.zip).

## Манометр в 3D и на телефоне

В сцене выберите «Манометр крупно». На телефоне выберите насос, отметьте «Манометр 0–1,6 кПа» и включите непрерывный осмотр. [Инструкция для RTX](МАНОМЕТР.txt).

## Осмотр корпуса

В 3D-сцене нажмите «Корпус целиком». На телефоне выберите насос, отметьте «Осмотр корпуса» и включите непрерывный осмотр. Модель выделяет контур по двум фотографиям и фиксированному ракурсу сцены. [Инструкция для RTX](ОСМОТР%20КОРПУСА.txt).

## Кабинеты и ремонт

После запуска START_RTX.bat откройте /admin. Первый вход — admin / admin. Создайте пользователей с ролями работника и начальника цеха. Работник входит через /worker, открывает камеру и сохраняет кадр кнопкой «Снять оборудование». В истории он оставляет комментарий и отправляет ремонт на проверку. Начальник через /brigadir открывает снимок и подтверждает ремонт или возвращает запись со статусом «Не исправлено». Для доступа через Radmin обновите также архив шлюза.

Для уже установленного локального шлюза Hack102-LAN обновите [host/backend.py](Hack102-LAN/host/backend.py) в его папке host и перезапустите шлюз. Прежняя HTTPS-ссылка mobile.html откроет форму входа.
