# OilTrace — детекция следов масла на оборудовании

Отдельный локальный проект. Папка:
`C:\Users\ZiganshinShamil\Desktop\Хакатон 102 v2\детекция масла`

**Результат: рабочий автоматический прототип с двумя обученными моделями и экспортом масок. Надёжность обнаружения тонких подтёков на оборудовании пока не подтверждена: на реальных фотографиях есть заметные пропуски и ложные выделения. Это не готовый промышленный сигнализатор утечки.**

## Запуск

Дважды нажмите **START.bat**. Приложение откроется по адресу http://127.0.0.1:8766.

Если политика компьютера не позволяет запускать PowerShell-скрипты, откройте терминал в этой папке и выполните:

```powershell
.\.venv\Scripts\python.exe app.py
```

Менять системную политику не требуется. Затем откройте указанный адрес вручную.

Приложение привязано только к 127.0.0.1. Фотографии не отправляются во внешние сервисы. Tailscale и Ollama для запуска не нужны. Своя `.venv`, модели, исходники, фотографии и результаты находятся здесь; проект ржавчины не используется во время работы.

## Как пользоваться

1. Выберите реальный пример или загрузите JPG/PNG/WebP.
2. Для своего фото нажмите «Найти следы масла». Выделение автоматическое, без ручных точек и рамок.
3. Сравните наложение с оригиналом. Доступны бинарная маска и рамки найденных областей.
4. Измените порог уверенности. Уменьшение порога повышает чувствительность, но может выделять детали, грязь и тени.
5. Скачайте маску PNG, наложение PNG и JSON. Экспорт учитывает текущий порог и использует точные сохранённые маски отдельных объектов.

Nano выбран основным как более быстрый вариант. Medium доступен для сравнения; больший размер не гарантирует лучшее качество. Вход модели — 640, 960 или 1280 px; стандарт — 960. Фотографии нормализуются с учётом EXIF и ограничиваются 2048 px по большей стороне. Максимальный файл — 32 МБ, исходное разрешение — 24 мегапикселя.

Порог по умолчанию **0.80** — консервативная настройка интерфейса, а не результат оптимизации по размеченному тесту. Внутри сохраняются предложения начиная с 0.05. Уверенность относится к предсказанию класса `oil`, она не калибрована как вероятность реальной утечки. Превью использует 8-битную карту уверенности объектов: около границы порога возможны небольшие различия с точным экспортом. Это не пиксельная вероятность масла.

«Нет выделений» означает только отсутствие предсказаний выше порога. Это не подтверждение исправности. Маска выделяет следы, похожие на масло, но не устанавливает химический состав жидкости, источник и факт продолжающегося течения. Для подтверждения активности нужны повторные наблюдения/видео либо осмотр.

## Модели

Скачаны обученные YOLO26 instance-segmentation модели с единственным классом **oil**:

- Nano: https://huggingface.co/kareem1232/spill_leak_detection_nano , revision `26eeaf9464458c81e106d019caa4ad1db43b41ba`.
- Medium: https://huggingface.co/kareem1232/spill_leak_detection , revision `7c8352a8d0257c1fd4d10f8d56e16902cbd02e24`.
- Библиотека: https://github.com/ultralytics/ultralytics , установленная версия зафиксирована в `requirements-lock.txt`.

Обучение или дообучение здесь не выполнялось. Сведения о назначении проверены по содержимому checkpoint: архитектура YOLO26n/m-seg, имя класса oil, вход обучения 640. Подробной публичной карточки с происхождением обучающей выборки нет. Внутреннее имя датасета `Oil-Segmentatiion-1` не позволяет подтвердить, насколько он представляет оборудование вашего типа.

В `models/` сохранены оригинальные `.pt`, извлечённые `.safetensors`, конфигурации архитектур и метаданные. `convert_models.py` извлекает тензоры с ограниченным unpickler: классы из checkpoint заменяются инертными объектами. Приложение загружает тензоры через safetensors, архитектуру строит из установленной библиотеки; **все ключи и формы проверены strict=True**. SHA-256 — `research/integrity.json`.

В checkpoint автор сохранил validation mask mAP@50 около 0.833 для Nano и 0.826 для Medium. **Это метрики автора на его данных, не наши измерения на оборудовании.** Нельзя выдавать их за точность этого проекта на фотографиях насосов. Веса содержат указание AGPL-3.0; отдельные подробные условия и данные обучения публичной карточкой не описаны.

## Реальные результаты и ограничения

Обработаны обеими моделями **13 реальных фотографий** оборудования: насосы, гидроцилиндры, соединения и трансмиссия. Это 26 предсказаний. Результаты не отбирались по удачности.

- `outputs/Все результаты.html` — автономная галерея всех фото: оригинал, Nano, Medium и ссылки на источники.
- `outputs/demo_comparison.jpg` — компактное сравнение с удачным примером, пропуском и сложной поверхностью.
- `outputs/interface_demo.jpg` — скриншот работающего приложения.
- `outputs/comparison.json`, `outputs/summary.json`, `outputs/comparison.log` — полные данные сравнения и время CPU.
- `samples/sources.json` — источники каждой фотографии.
- `outputs/<идентификатор>/` — оригинал, маска, наложение, карта уверенности объектов, сжатые маски всех предложений и JSON.

На фото автомобиля с большой лужей обе модели находят лужу. На отдельных фото мелких подтёков модель пропускает масло. При снижении порога некоторые целые детали и участки фона выделяются ошибочно; на фото Schaeff остаются и высокоуверенные ошибочные выделения. Нельзя использовать только один удачный пример для оценки качества.

У этих снимков нет эталонных масок и проверенных отрицательных примеров. IoU, precision, recall и качество классификации «масло/не масло» здесь **не измерялись**. Число фото с найденной областью не является recall. Фотографии не использовались нами для обучения; их отсутствие в исходном обучении автора модели не установлено. Некоторые изображения похожи или относятся к одной теме: выборка не считается набором 13 независимых промышленных случаев. Открытые лицензии на повторную публикацию всех фотографий не установлены; источники сохранены для локальной демонстрации.

Работа на процессоре; фактическое время каждого запуска записано в JSON. Время первого запроса дополнительно включает загрузку модели. Надёжное качество на вашем оборудовании потребует размеченной целевой выборки, в том числе чистых деталей, воды, смазки, грязи, теней и старых следов. Обучение и тест следует разделять по оборудованию/съёмкам, а не по соседним кадрам одного объекта. Для оценки лучше отдельно считать точность маски и обнаружение утечки на уровне оборудования.

## Что найдено при поиске готовых проектов

- **PowerOL** — профильный набор 4 364 изображений энергетического оборудования с прямоугольной разметкой десяти типов утечек. https://github.com/xushuai7/PowerOL . Готового обученного детектора в репозитории нет; это кандидат для последующего обучения, а не установленная модель.
- **Kether180/leak-detection-thesis** — классификация oil/water/no-leak; автор указывает, что готовые веса и данные не включены. https://github.com/Kether180/leak-detection-thesis .
- **MSunusi/pipeline-leak-detection** — опубликованные веса есть, но фактические классы Gas Leak и Water Leak; для масла не использован. https://github.com/MSunusi/pipeline-leak-detection .
- **LeakSAM-T** — предназначен для протечек в туннелях метро, не профильная модель масла на оборудовании. https://github.com/Zhiyao-code/LeakSAM-T .
- **AnoDFDNet** — поиск отличий и аномалий между парой изображений; другой входной сценарий. https://github.com/wangle53/AnoDFDNet .
- **AnoTGOL** — генерация/разметка изображений нефтяных пятен у трансформаторов, не готовый универсальный детектор. https://github.com/chenroa/AnoTGOL .
- Морские SAR/Sentinel-1 oil-spill модели исключены: они не подходят к обычным фото машин.
- Ранее подготовленная Qwen3-VL + SAM2 цепочка не используется как автоматический oil-детектор: предыдущие результаты на насосах были слабыми, а SAM по ручной подсказке не распознаёт масло самостоятельно.

Результаты поиска и ответы API сохранены в `research/`. Обе установленные модели взяты из публичных Hugging Face repositories; собственного публичного GitHub-репозитория их обучения обнаружить не удалось. Это рабочая исходная база для дальнейшей проверки, не доказанный лучший детектор промышленных утечек.

## Воспроизведение

Собственная фотография:

```powershell
.\.venv\Scripts\python.exe predict.py "C:\путь\к\фото.jpg" --out ".\outputs\my-photo" --model nano --confidence 0.8 --imgsz 960
```

Повторить сравнение всех фото:

```powershell
.\.venv\Scripts\python.exe compare_models.py
```

Проверить работающее приложение:

```powershell
.\.venv\Scripts\python.exe verify_app.py
```

Проверка охватывает настоящий upload, экспорт масок при порогах 0.20/0.80/0.95 с побитовым сравнением, экспорт JSON, некорректный файл/режим, отсутствующий результат и отдельный инференс с заблокированными сетевыми socket-вызовами. Итог — `outputs/API_CHECKS.json`, журнал — `outputs/verification.log`.

Зависимости: Python 3.11, PyTorch CPU, Ultralytics, Flask, Pillow, OpenCV, safetensors. При восстановлении окружения:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --extra-index-url https://download.pytorch.org/whl/cpu -r requirements-lock.txt
```

Оригинальные модели повторно скачивает `download_models.py`; преобразование выполняет `convert_models.py`. Первое скачивание требует сети. В обычной работе сеть не требуется.
