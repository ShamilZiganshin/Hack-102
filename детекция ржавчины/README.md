# RustLab — локальная сегментация ржавчины

Все материалы проекта находятся в этой папке. Модель уже скачана, окружение установлено, обучение для запуска не требуется.

## Запуск

Дважды нажмите **START.bat**. Откроется http://127.0.0.1:8765.

Приложение использует процессор, запускается только на 127.0.0.1 и не отправляет фотографии в облако. Интернет после установки не нужен. Если выполнение PowerShell-скриптов ограничено политикой компьютера, запустите из этой папки `.venv\Scripts\python.exe app.py` и откройте адрес вручную. Менять политику выполнения не требуется.

В интерфейсе доступны загрузка фотографии, оригинал, наложение, бинарная маска, карта уверенности, регулировка порога и экспорт PNG. Порог по умолчанию — 0.50. После изменения порога метрики примера скрываются, поскольку они посчитаны при 0.50. Карта уверенности не калибрована. Процент площади относится ко всему изображению, а не к поверхности трубы: для последнего нужна отдельная сегментация самого оборудования.

Файлы результата сохраняются в `outputs/<идентификатор>/`: оригинал, наложение, маска, карта уверенности, точная float32-карта `probability.npy` и JSON. Демонстрационные снимки `01`–`15` имеют эталонную разметку. Для собственных снимков без разметки IoU не показывается.

## Что установлено

**UNet++ с ResNet50**, обученная на коррозии, из репозитория Matěj Frič:
https://github.com/matejfric/corrosion-segmentation

Исходники зафиксированы на commit `5af4a651ac1c97a67b23f71bbeb9def1e43f1ea2` и сохранены в `repositories/ostrava/`. Обученные веса получены из открытого DagsHub-эксперимента автора, версия 1:
`pytorch-unetplusplus-resnet50-imagenet-with-augmentation`;
run `aa88cf5d7b174fd4840d3851af51509f`.

Датасет: Frič, M. (2024), Corrosion in Industrial Complexes in Ostrava, https://doi.org/10.5281/zenodo.11235637, CC BY 4.0. Архив датасета сохранён целиком; распакованы validation и test. Исходный checkpoint `models/ostrava_original.pth` сохранён; для повседневной работы используется `models/ostrava_unetpp_resnet50.safetensors`. Все тензоры строго совпадают с архитектурой (strict=True). В процессе преобразования классы из pickle заменялись инертными объектами; приложение не исполняет исходный pickle. SHA-256 находится в `research/integrity.json`.

Модель не обучалась и не дообучалась здесь. Это воспроизведение и улучшение режима инференса готовой модели. Веса около 196 МБ. Python 3.11, PyTorch CPU, segmentation-models-pytorch 0.5.0. Все фактические версии зафиксированы в `requirements-lock.txt`.

## Измеренное качество

Сначала на **15 validation-изображениях** сравнили пять фиксированных режимов с порогом 0.50. Выбран режим с наибольшим средним IoU; затем его зафиксировали в `config.json` и оценили на **15 test-изображениях**, которые не использовались для выбора режима.

| Режим | Validation mean IoU | Validation mean Dice |
|---|---:|---:|
| Исходный 256 | 0.8473 | 0.9121 |
| 256 + отражение | 0.8427 | 0.9090 |
| 384 | 0.8611 | 0.9219 |
| 512 | 0.8463 | 0.9132 |
| **256 + 384 + отражения** | **0.8632** | **0.9226** |

| Режим | Test mean IoU, исходное разрешение | Test mean Dice | Время предсказания CPU |
|---|---:|---:|---:|
| Исходный 256 | 0.8643 | 0.9250 | 0.42 с |
| **Качественный** | **0.8897** | **0.9405** | **2.97 с** |

Время — среднее время forward-проходов на этом компьютере (Intel, 16 ГБ ОЗУ, 4 потока PyTorch), без запуска Python и сохранения изображений. Первый запрос в интерфейсе включает загрузку модели. Качественный режим усредняет четыре карты: 256 и 384 px, с горизонтальным отражением и без; затем билинейно восстанавливает карту до исходного размера. Увеличение до 512 само по себе не дало лучшего результата на валидации.

Контроль воспроизводимости: при исходном разрешении оценки автора 256×256 локально получены IoU **0.87899118**, Dice **0.93322878**, что совпадает с журналом автора до погрешности float32. Это важно: оригинальная модель обучалась на диапазоне **0..255**, с вычитанием ImageNet mean/std **без деления на 255**. Стандартное преобразование в 0..1 для этих конкретных весов было бы неверным.

Все метрики по отдельным изображениям и агрегаты: `outputs/benchmark.json`. Полный журнал: `outputs/benchmark.log`. Сравнение оригиналов, предсказаний, эталонов и ошибок: `outputs/demo_comparison.jpg`. В карте ошибок зелёный — верно найденные пиксели ржавчины, оранжевый — ложные выделения, синий — пропуски.

Это небольшой тестовый набор исходной работы, а не независимая промышленная сертификация. Авторы уже использовали этот test для сравнения архитектур. Нельзя трактовать эти цифры как гарантированную точность на вашем предприятии или как процент правильных фотографий. Нет отдельной проверки на большом наборе чистых объектов. Не оценивались видео, специальные покрытия, изменение освещения и микроскопически мелкие пятна. Границы формируются из карт 256/384 px; результат в 2048 px не означает 2048 px независимых деталей.

Для очень мелких очагов на ваших трубах следующий содержательный шаг — собрать целевые снимки, отдельно разметить ржавчину и чистые похожие поверхности, отложить независимый test по объектам/местам съёмки и дообучить сегментатор. Увеличение разрешения, тайлы или SAM-уточнение следует принимать только после такой проверки: они могут также усилить ложные выделения.

| RustSEG | Классификация, Grad-CAM++ 28×28, затем уточнение маски | Менее подходящая отправная точка для приоритета точных границ |
| TheShreyanshiDwivedi/corrosion-detection | DeepLabV3+ и YOLO26m-seg; в README для YOLO mask mAP@50 0.220 | Не выбран без подтверждённого преимущества |
| Matiullah00999/corrosion-segmentation | SegFormer mit_b3, но gated weights и в карточке указан Oxford Pet | Не выбран из-за неоднозначной карточки и доступа |

Ссылки и снимки исходных метаданных сохранены в `research/`. Эти проекты не сравнивались на единой выборке локально, поэтому выбранная модель — наиболее подходящее воспроизведённое решение среди изученных, а не доказанный мировой лидер. Метрики из разных датасетов напрямую несопоставимы. Репозиторий выбранной модели не содержит явного LICENSE; права на код и веса следует уточнять у автора перед распространением продукта.

## Командная строка

Из этой папки:

```powershell
.\.venv\Scripts\python.exe predict.py "C:\путь\к\фото.jpg" --out ".\outputs\my-photo" --mode quality --threshold 0.5
```

Повторить измерение (несколько минут):

```powershell
.\.venv\Scripts\python.exe benchmark.py
```

Полная исходная среда автора не нужна. При восстановлении окружения:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --extra-index-url https://download.pytorch.org/whl/cpu -r requirements-lock.txt
```

`download_assets.py` сохраняет публичные оригинальные материалы; `convert_checkpoint.py` извлекает tensor-only веса из оригинального checkpoint. Уже готовый `.safetensors` входит в папку проекта. `verify_demo.py` проверяет локальный HTTP API, реальный upload, экспорт PNG, неверный файл, сохраняет точные карты для примеров и контрольные суммы. Последняя проверка — в `outputs/smoke_checks.json` и `outputs/verification.log`.
